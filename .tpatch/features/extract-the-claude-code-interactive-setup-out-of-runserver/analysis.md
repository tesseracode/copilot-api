# Analysis

`runServer` measures 99 lines against a `max-lines-per-function` limit of 100 inherited from the shared `@echristian/eslint-config`. The rule is configured with `skipBlankLines: true` and `skipComments: true`, so that figure is real code rather than formatting, and adding the catalog scheduler already consumed the remaining headroom — the call had to be condensed onto one line to keep lint green. The next startup addition fails outright.

The rule is reporting a genuine cohesion problem rather than an arbitrary threshold. `runServer` currently owns proxy and logging setup, option-to-state transfer, auth bootstrap, catalog and scheduler startup, 1M-context environment detection, Claude Code interactive onboarding, and finally server listen plus the development SIGINT handler. That is seven responsibilities in one function, and the `if (options.claudeCode)` block is 51 of the 99 lines — more than half of it.

That block is the right thing to move for reasons beyond its size. It runs only behind an opt-in CLI flag, so it is absent from every normal startup. It is interactive, issuing two `consola.prompt` selections and writing to the clipboard, which makes it a fundamentally different kind of work from binding an HTTP listener. Being interactive also makes it untestable in place: any attempt to drive `runServer` would block on the first prompt. Extraction converts it into a unit that can be exercised with a stubbed prompt.

Relaxing the rule is the worse option. `eslint.config.js` currently only sets `ignores` and passes a prettier plugin through to the shared config, so raising the limit means introducing a local rule override — a fork customization that must survive upstream config bumps. The override would also be global rather than file-scoped, so loosening the threshold to accommodate one function would suppress the same signal everywhere else in the codebase. The surrounding configuration is not unusually strict either, with `max-lines` at 800 and `complexity` at 16, which makes 100 a normal threshold rather than an outlier worth fighting.

The extraction itself is mechanical and low risk. The block is contiguous, reads only `state.models` and the locally computed `serverUrl`, and its sole outward effect is setting `state.is1MContext`, which is module-scoped and therefore unaffected by the move. Passing `serverUrl` as a parameter is enough to make the new function self-contained. Because the block is guarded by `options.claudeCode`, the blast radius is limited to users of that flag, and the ordering constraint that matters — the env-var 1M detection running before the interactive selection ORs into it — is preserved simply by keeping the call site where the block already is.
