# Feature Request: Refresh the cached Copilot model catalog on a timer instead of loading it once at startup. cacheModels() currently runs only at startup (src/start.ts:66) with no refresh timer, so a long-running proxy can never see models added upstream and routes on an arbitrarily stale snapshot; a live probe measured the catalog moving 40 to 41 models over three days while upstream advertises cache-control private max-age=21600. Mirror the proven pricing-scheduler pattern: single-flight refresh, non-fatal failure that keeps the last good catalog, unref'd timer, and SIGINT/SIGTERM cleanup. Because adopting a catalog change silently alters routing mid-process, the refresh must be observable (log added/removed model IDs) and operators running compatibility canaries must be able to pin a catalog by disabling refresh via a configurable interval where zero means never. Depends on the provenance markers so catalog changes are attributable rather than silent.

## Description

Mirror the proven pricing-scheduler pattern: single-flight refresh, non-fatal failure that keeps the last good catalog, unref'd timer, and SIGINT/SIGTERM cleanup. Because adopting a catalog change silently alters routing mid-process, the refresh must be observable (log added/removed model IDs) and operators running compatibility canaries must be able to pin a catalog by disabling refresh via a configurable interval where zero means never. Depends on the provenance markers so catalog changes are attributable rather than silent.
