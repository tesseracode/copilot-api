# Analysis

Two hardcoded model lists had rotted in the three weeks since the last session, and both failures were silent.

`MODEL_ID_MAP` in `src/lib/model-mapping.ts` translates Anthropic's dash version format to Copilot's dot format. Six of its eight targets no longer exist in the catalog (`claude-opus-4`, `claude-opus-4.5`, `claude-opus-4.6`, `claude-sonnet-4`, `claude-sonnet-4.5`, `claude-sonnet-4.6`); only `claude-haiku-4.5` and `claude-opus-4.7` remain. Meanwhile `claude-opus-4.8` is live and absent from the map, so an Anthropic client sending `claude-opus-4-8` received `claude-opus-4-8` back — an ID no catalog entry matches — and the reverse direction returned `claude-opus-4.8` where Claude Code expects the dash form. `claude-opus-5` and `claude-sonnet-5` happen to survive only because a single-digit version contains no dot to convert.

`MODEL_ALIASES` in `src/lib/copilot-pricing.ts` matches GitHub's pricing table by exact display name. Running the real pipeline against live data showed ten live models with no pricing metadata, including `gpt-6-astra`, `grok-4.5`, `grok-4.6` and `claude-opus-5`. Two of those were regressions rather than omissions: `gemini-3.6-flash` and `claude-sonnet-5` had been matching and broke when a promotion footnote appeared on one name and disappeared from the other. That is the decisive detail — the pricing table is documentation, so its names carry markdown footnote markers that come and go for reasons unrelated to the model, and exact-string matching cannot survive them.

Both are instances of the failure `CLAUDE.md` already names: deriving behavior from enumerated model lists rather than from the live catalog. The correction is the same in both cases, because both transformations are **format conventions rather than model capabilities**. Anthropic writes a minor version as `-N` and Copilot writes it as `.N`; a documentation table title-cases and spaces what the catalog lowercases and dashes. Neither depends on what a model can do, so both can be derived by rule and neither needs catalog gating — confirmed by the existing tests, which assert `claude-sonnet-4-6` maps correctly against a catalog that does not contain it.

The derived version rule reproduces all eight existing map entries exactly, so it fully subsumes the enumeration; the map is retained only as an override layer for a model that might break the pattern. The minor version is bounded to two digits so an unstripped date suffix such as `claude-sonnet-4-20250514` can never be read as one.

The pricing change reverses an explicit earlier decision, recorded in the test `reports unmatched model names rather than guessing`. That rule was conservative about billing data, which is a reasonable instinct, but the measurement shows the conservatism was the more expensive option: it silently dropped pricing for ten real models. The asymmetry justifies the reversal — a derived entry for a model that does not exist is inert, because `pricingForModel` is only ever queried with live catalog IDs, whereas a missing entry for a model that does exist is a visible gap in `x_copilot_pricing`. The `unmatched_models` diagnostic is preserved for the case that still matters, prose rows such as `Claude Opus 4.8 (fast mode) (preview)` that are documentation rather than models.
