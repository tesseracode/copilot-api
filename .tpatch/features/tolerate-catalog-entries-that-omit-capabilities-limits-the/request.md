# Feature Request: Tolerate catalog entries that omit capabilities.limits. The Model type declared limits as required, but the live catalog serves gpt-41-copilot (type completion) and text-embedding-3-small-inference without it, and both also omit supported_endpoints so they fall through to the Chat path. A request naming gpt-41-copilot with no max_tokens reached handler.ts reading .max_output_tokens through the absent object and returned HTTP 500, proven with a route test against the verbatim live catalog shape. The embeddings route had the same unguarded read of limits.max_inputs. Make limits optional so the type matches the served data, guard both production reads, fix the script call sites the type change surfaces, and declare the previously undeclared supports fields streaming, structured_outputs, vision, adaptive_thinking, min_thinking_budget and max_thinking_budget.
